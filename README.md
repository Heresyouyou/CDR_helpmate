# CorelDRAW 助手

一个常驻屏幕的置顶小窗，管住 **所有已打开的 CorelDRAW 文件**：按文件名切换，
每个文件单独一套「默认对象属性」——线宽、轮廓颜色、填充，各自独立，互不干扰。
改完立刻生效，之后用 **B 样条、贝塞尔、手绘、钢笔** 画的每一条线都直接是你要的样式，
不用再进「对象样式」泊坞窗翻菜单。

已在本机 CorelDRAW Graphics Suite 2024（25.0.0.230）+ Python 3.12 实测通过。

---

## 启动

**方式一：双击 `CDR助手.exe`**（推荐，无需 Python 环境）

**方式二：源码运行**，双击 `启动.bat`（需要 `D:\Python 3.12.4`）

打开后先运行 CorelDRAW 并打开至少一个文件，助手会自动连上并列出文件名。
连不上时标题栏圆点是红的，状态栏会提示。

### 为什么线型是「改选中对象」而不是默认值

这是 CorelDRAW 的 API 限制，不是偷懒。翻了它自带的类型库定义
（`IVGStyleOutline`），默认样式的轮廓属性表里只有：

```
Type / Width / Color / LineCaps / LineJoin / MiterLimit /
Justification / AdjustDashes / NibAngle / NibStretch /
WidelineWidth / ScaleWithShape / BehindFill / Overprint
```

**没有 Style（线型）这一项**，`Style` 只有 getter、而且返回的是父样式对象。
线型只存在于对象级 `IVGOutline` 上（`Outline.Style = OutlineStyles.Item(n)`）。

所以：CorelDRAW 本身也不支持「设一个默认线型让新画的线自动带虚线」。
这个工具能做的是——你先选中一条线，点一下线型按钮，立刻改过去。

### 一键按线型分组

点「按线型分组 实线 / 虚线」，遍历**当前文档的所有页面、所有图层**，
每个图层各生成两个组合：

| | 判据 | 结果 |
|---|---|---|
| 实线 | `Outline.Style.DashCount == 0` | 合成名为「实线」的组合 |
| 虚线 | `Outline.Style.DashCount > 0` | 合成名为「虚线」的组合 |

- **判据为什么用 DashCount**：CorelDRAW 25 的 `LineStyle` 对象上没有 `Name`，
  `Application.LineStyles` 也不存在；线型集合挂在 `Application.OutlineStyles` 上
  （27 项，Index 1–27，实线是 0、不在集合里），而且只能按 Index 取。
  `DashCount` 是唯一可靠的读数：0 = 实线，≥1 = 虚线族（单段、双段、点划线…）。
- **跳过**：空图层、锁定的图层、没有轮廓的对象（文本、位图）、已经是组合的对象
  （不往组合里套组合）。
- **某一类不足两个对象时不建组** —— 单个对象组合起来没有意义。
- 整批包在一个 `BeginCommandGroup` 里，在 CorelDRAW 里**一次 Ctrl+Z 就能整体撤销**。
- 完成后弹窗列出每个图层的实线/虚线条数，状态栏留一行汇总，明细同时写 `debug.log`。

两个坑（代码里已注释，别改回去）：

1. **分组前必须 `layer.Activate()`**。`CreateShapeRangeFromArray().Group()` 会把新建的
   组合并到「当前活动图层」，不激活就等于把别的图层的对象整体搬走。
2. **每处理一类都要重新读 `layer.Shapes.Count`**，分组之后旧的对象引用会失效。

### 自动更新检查

启动 3 秒后静默查一次线上版本，**只有线上更高才弹窗**。版本相同、线上读不到、断网 —— 一律不打扰，只在 `debug.log` 里记一行。

**先内网、后公网**：

1. 先探 `https://kust.work/cdr`（DNS + TCP 建连，1.2 秒超时，比 ICMP 更贴近“能不能真拿到东西”）；
2. 通了就读内网版本；内网**不通**、或内网**读了但失败**（404 / 超时），自动回落到 `https://sjck.kust.work/cdr`；
3. 弹窗里写明「版本来源」，下载按钮也优先给内网的 exe 地址。

**接口约定**（`/cdr`，JSON 与纯文本都认）：

```json
{
  "version": "1.3.0",
  "url_lan": "http://kust.work/cdr/CDR助手.exe",
  "url": "https://sjck.kust.work/cdr/CDR助手.exe",
  "notes": "1. 新增按线型分组\n2. 修复多文档切换时线宽串档"
}
```

- 只有 `version` 必填；`url` / `url_lan` / `notes` 可省。
- 返回纯文本也认：正文里第一个像 `1.3.0` 的数字串会被当成版本号（`latest: v1.3.0` 也行）。
- 版本按数字段比较：`1.10.0 > 1.9.9`，`v` 前缀可有可无。

**调试**：两个地址都能用环境变量顶掉，本地起个假接口就能验弹窗：

```
set CDR_UPDATE_LAN=http://127.0.0.1:8765/cdr
set CDR_UPDATE_WAN=http://127.0.0.1:8765/cdr
```

**服务端（已部署，2026-11-23）**

| 站点 | 挂在哪 | 说明 |
|---|---|---|
| `https://kust.work/cdr` | 门户 Flask（5555）`web_app.py` 末尾新增 `/cdr`、`/cdr/<file>` | 内网优先 |
| `https://sjck.kust.work/cdr` | GeoKB 服务（5556）`server/app.py` 末尾新增同名路由 | 公网兜底 |

两边读同一份发布目录 `D:\PostNews\cdr_release\`（`cdr.json` + `cdr-helper.exe`），
**每次请求都读盘** ⇒ 发新版只换文件，不用重启 Flask。

JSON 里的 `url` 写相对路径 `/cdr/cdr-helper.exe` 即可，服务端按请求 Host 补绝对地址。
注意 sjck 侧因为反代终止了 TLS，补出来的是 `http://` —— 客户端会把 https 源上的 http
地址自动升回 https（`pick_download_url`），实际下载不会降级。

**发新版就三步**：

```bash
# 1) 改源码里的 APP_VERSION，重新打包
python -m PyInstaller CDR助手.spec --noconfirm
# 2) 一条命令发布（复制 exe + 写 cdr.json，版本号自动取源码里的）
python publish.py "1. 修了什么\n2. 加了什么"
# 3) 验两条
curl -s https://kust.work/cdr && curl -s https://sjck.kust.work/cdr
```

**一键替换**（点「是」之后全自动，不需要再找文件）：

1. 下载到 exe 同目录的 `CDR助手.exe.new`，带进度百分比；先校验 PE 头与体积，防止把 404 页面当程序装进去；
2. 把**正在运行**的 exe 改名成 `CDR助手.exe.old`（同盘 rename 不受映像锁限制）；
3. 新文件补回原名，`subprocess` 起新进程，本进程随即退出；
4. 新版第一次心跳就把 `.old` 删掉（旧进程没退干净时自动重试，最多 12 次）。

**启动新进程前必须清 `_MEIPASS` / `_PYI_*` 环境变量**（代码里 `spawn_new_instance` 已处理）：
不清的话新进程会沿用父进程的单文件解包目录，父进程一退目录消失，新进程立刻报
`base_library.zip` 找不到。

**失败兜底**：改名被安全软件拦住时，改写一个临时 `.bat`（等本进程退出 → `move` → `start`）；
连批处理也起不来，才退回打开下载页。源码模式（`.pyw`）没有可替换的 exe，直接开下载页。

### 多文档是怎么处理的
- 标签栏每 3 秒自动同步一次 CorelDRAW 的文档列表：新开的文件自动出现，
  关掉的文件自动消失；当前文件被关就自动跳到第一个。
- 点标签时会让 CorelDRAW 也切到那个文件（`Document.Activate`），
  所以你看到的画面和助手里的设置始终是同一个文件。
- 每个文件的值都是**从该文件本身读回来的**，不是助手记的账 ——
  你在 CorelDRAW 里手动改过默认值，切回来也能正确显示。

### 色板从哪来

切到某个文件时读一次，规则是：

1. 该文件的**文档调色板**里有 8 个以上颜色 → 用它（说明你在文件里攒了自己的色板）；
2. 否则用标记为 `Default` 的那个调色板（标准调色板，实测 100 色）。

每个文件的色板单独缓存，切来切去不会重复读。连不上时退回内置 10 个基础色。

## 它到底改了什么

改的是**当前文件**的「默认对象属性」样式，也就是「对象样式」泊坞窗里
`默认对象属性 → 图形`（内部名 `~graphic~`）和 `艺术笔`（`~artisticmedia~`）。
与 CorelDRAW 官方 SDK 用的是同一套接口。

**生效范围**：

- 只影响**之后新建**的对象，已经画好的线不会变。
- 默认属性是**文档级**的，存在各自的 `.cdr` 里 —— 这正是「每个文件一套」的原因。
- 想让所有**新文档**都默认这套值，仍需在 CorelDRAW 里做一次
  **工具 › 将设置另存为默认设置**（那是全局配置，助手不代劳）。

## 开机自启后会发生什么

打开 `○ 开机自启` 后，助手会写一条注册表启动项
（`HKCU\Software\Microsoft\Windows\CurrentVersion\Run\CorelDrawHelper`）。

之后每次开机助手都会常驻：

- CorelDRAW 没开 → 自动折叠成一条标题栏，不占地方；
- CorelDRAW 打开了 → 自动展开、连接、列出文件；
- CorelDRAW 关掉了 → 又自动折叠。

关掉这个开关就会删除那条注册表项。

## 几个坑（代码里已绕过，别改回去）

1. **`cdrMillimeter` 在 COM 层是 3，不是 VBA 文档写的 4。**
   传 4 得到厘米，线宽直接大 10 倍。代码用 `resolve_mm_unit()` 靠页面尺寸反推。

2. **`StyleOutline.Width` 的 getter 对小值恒返回 0。**
   写 0.5mm 读回来是 0，但写入其实成功了。读取必须走
   `GetPropertyAsString("outline")` 解析 JSON（`width` 单位是万分之一毫米）。

3. **`Fill.UniformColor` / `PrimaryColor` 都是只读的**，`ApplyUniformFill()` 也不存在。
   填充色只能 `SetPropertyAsString("fill", json)`，颜色串要带模型前缀和 GUID。

4. **CorelDRAW 不注册运行对象表**，`GetActiveObject` 一律失败，只能用 `Dispatch`
   （它复用已运行实例，不会新开进程）。

5. **`Document.Activate()` 会泵 COM 消息**，能把 Tk 挂起的延迟写入提前触发。
   切换文档时必须先 `after_cancel` 掉待执行的写入，否则会把 A 文件的值写进 B 文件。

6. **调色板：`Application.Palette` 不存在**，要遍历 `Application.Palettes`，
   用 `pal.Default` 判断默认调色板；`Document.Palette`（文档调色板）新建时往往只有 1 色。
   取色 `pal.Color(i).HexValue`，下标从 **1** 开始。

7. 文档若是 CMYK 色彩模式，写入的 RGB 会被转到 CMYK 存储，回读有几个色阶偏差。
   这是色彩管理行为，不是 bug。

8. **默认样式的轮廓没有线型字段**。`IVGStyleOutline` 的类型库定义里
   `Style` 只有 getter，且返回父样式；`Document.OutlineStyles` 不存在，
   线型集合挂在 `Application.OutlineStyles` 上（27 种）。
   `CopyAssign` / `SetProperties` / `ToString` 这些在 `dir()` 里看得到，
   但动态绑定调用一律报「找不到成员」，是类型库里的 restricted 方法。

9. **本机若存在 `gen_py` 类型库缓存，`win32com.client.Dispatch` 会切成早期绑定**，
   参数校验和「属性 vs 方法」的判定都会变（例如 `doc.Selection` 会从方法变成属性）。
   打包后没有缓存，行为就不同了。所以代码里固定用
   `win32com.client.dynamic.Dispatch`，保证两种环境一致。

10. `Document.Selection` 在动态绑定下是个方法，**取选区要用 `Document.SelectionRange`**。
